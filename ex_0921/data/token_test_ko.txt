대규모 언어 모델은 입력 가능한 최대 토큰 수가 정해져 있으므로 문서의 문자 수만 확인하는 것보다 실제 토큰 수를 측정하는 것이 중요합니다. 
특히 한국어는 하나의 글자가 항상 하나의 토큰으로 대응되지 않기 때문에 영어 문서와 동일한 문자 수라도 토큰 수가 달라질 수 있습니다.

데이터 엔지니어링에서는 다양한 데이터 소스를 하나의 분석 환경으로 연결해야 합니다. 
예를 들어 공장 설비의 PLC 데이터, MES 생산 이력, 품질 검사 결과, 작업자 입력 정보가 서로 다른 시스템에 저장될 수 있습니다. 
이 데이터를 연결하려면 공통 키를 정의하고 시간 기준을 맞추며 스키마 변경에 대응해야 합니다.

RAG 시스템에서는 문서 로딩, 텍스트 분할, 임베딩 생성, 벡터 저장, 검색, 프롬프트 구성, 답변 생성의 순서로 데이터가 이동합니다. 
문서 분할 단계에서 생성된 청크는 이후 검색 품질에 직접적인 영향을 줍니다. 
검색 질문에 필요한 문맥이 하나의 청크 안에 포함되어 있으면 모델이 더 안정적으로 답변할 수 있습니다.

토큰 기준 분할기를 사용할 때는 chunk_size를 모델의 컨텍스트 윈도우보다 충분히 작게 설정해야 합니다. 
검색 결과 여러 개를 동시에 프롬프트에 넣는 경우 시스템 프롬프트와 사용자 질문이 차지하는 토큰도 고려해야 합니다. 
따라서 운영 환경에서는 문서 토큰 수뿐 아니라 검색 결과 개수와 답변 길이까지 함께 관리하는 것이 좋습니다.
